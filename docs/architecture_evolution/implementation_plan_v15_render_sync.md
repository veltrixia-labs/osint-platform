# マップ描画のデータバインドと実行タイミングの最終調整計画

描画オブジェクト（パルス・アーク）が確実に、かつ正しい順序でマップ上に表示されるよう、ライフサイクル管理を厳格化します。

## User Review Required

> [!IMPORTANT]
> この修正により、描画プロセスが `invalidateSize` の完了を確実に待つ構成になります。
> また、`overlayPane` を明示的に使用することで、描画オブジェクトがタイルの背後に隠れる問題を物理的に排除します。

---

## 提案される変更 (Proposed Changes)

### 1. データバインドの強化と事前ログ (`render.ts`)
*   `alerts` フェッチ後、`focusAlertId` に基づくターゲット探索を最優先で実行します。
*   ログ: `[Antigravity] Target Alert Found: {Title}` (見つからない場合は警告ログを出力し、不正な座標へのジャンプを阻止)。

### 2. 描画シーケンスの同期化 (`render.ts`)
*   `map.invalidateSize()` の直後に描画を開始するのではなく、以下の順序を保証します：
    1.  `setTimeout` で `invalidateSize()` を実行。
    2.  ログ: `[Antigravity] Map Container Ready (Size Invalidated)`。
    3.  描画関数（マーカー・アークのプロット）を 50ms 程度の追加ディレイを挟んで実行。
    4.  ログ: `[Antigravity] Drawing Pulse & Arc for: {ID}`。

### 3. レイヤー・オーバーレイの視認性確保 (`render.ts`)
*   `currentDynamicLayer` の作成時に、Leafletの `pane: 'overlayPane'` オプション、あるいは `zIndex` を明示的に考慮したマーカー設定を適用します。
*   `overlayPane` はデフォルトでタイルレイヤーより上に配置されますが、念のためマーカー側の `zIndexOffset: 1000` などの設定を追加し、視認性を最大化します。

### 4. 掃除と再描画の徹底
*   `updateMapFocus` (または相当する描画ループ) の直前で `layerGroup.clearLayers()` を確実に実行します。

---

## 期待される結果

1.  **確実な表示**: タイルが表示された後、100%の確率で赤いパルスとアークが「最前面」に現れる。
2.  **エラー耐性**: 万が一 ID が見つからない場合でも、地図が壊れたり変な場所に飛んだりしない。
3.  **透明性**: コンソールを確認するだけで、どのフェーズで描画が実行されたかが秒単位で把握できる。

---

## Verification Plan

### Manual Verification
1.  **コンソール・パトロール**: 指示された3つのログが順番通りに出力されているか確認。
2.  **タイル重なりチェック**: 地図をズーム・ドラッグしても、パルスリングがタイルの下に潜り込まないか確認。
3.  **データ整合性チェック**: フィード内の特定のアラートをクリックし、そのアラートのタイトルがログに表示され、地図上のポップアップと一致するか確認。
